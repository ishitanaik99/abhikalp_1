Captain · Agent 1 of 4

Shift assistant

Watches the order forecast, switches the store between Quiet, Normal, Busy and Very busy, asks you before calling extra staff, and briefs you in Hindi.

Technical details
Ledger · Agent 2 of 4

Stock checker

Every time a picker finds a shelf empty, Ledger trusts that item’s stock record less. When the record can’t be trusted, it hides the item from the app, sends a 30-second count and asks for a refill from the backroom.

Technical details
Relay · Agent 3 of 4

Rider-first packing

Decides which order goes to the pickers first, so the bag for the rider who arrives first is ready first. If a rider is late, it moves another order ahead.

Technical details
Promise · Agent 4 of 4

Missing items

Asks customers before they pay: if this item runs out, swap or refund? When an item is missing, it does exactly what the customer chose. It never guesses and never cancels the whole order.

Technical details
Optimiser · Plain code, not an agent

Fast optimiser

Batches orders, routes each trolley and assigns pickers every 5 seconds, in milliseconds. The agents change only its inputs and limits.

    About this prototype

    How the platform is built, what is simulated, and how to use the controls.

    The platform

    Four separate agents. Ledger, Captain, Relay and Promise are independent modules on a Python server. Each has its own prompt, its own tools, the events it wakes on, and plain-code “sense” logic that watches the store.

    How an agent decides. It sends a compact JSON view of the store to a Groq-hosted LLM, which answers with tool calls. Every call is checked against hard limits in code before it runs. If the LLM is off, over budget or slow, the agent uses its own rules, so the store never stops.

    How they stay in sync. Agents never call each other. They write only the shared-state fields they own; those writes raise events that the bus routes to the next agent, all within the same simulated second. The fast optimiser is plain code that reads what the agents set.

    The simulation and controls

    Two stores, same orders. One simulated dark store (8 aisles, 24 items, 6 pickers, 2 packers) runs twice on an identical stream of orders from 18:30 to 20:30: once with SyncStore and once with today’s static plan. Silent stock losses are built in (milk, chips, paneer, cola).

    All controls sit under Demo controls in the header. Run peak-hour demo restarts at 18:38 at 20× speed. Agent layer: Live runs the floor, Shadow only logs what the agents would do, Off shows the fail-safe. Decisions: switch between the Groq LLM and the agents’ rules.

    Create an event from Demo controls in the header: empty any shelf, make a rider late, or add a burst of orders. The Promise module has a checkout you can try yourself.
